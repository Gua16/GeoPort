# GeoPort 页面与服务退出需求

2026-10-12 Codex。状态：未验证。需求已记录，未实现、未运行验收；当前安装版仍为 0.1.2。

## 已提出的需求

点击“退出 GeoPort”后，停止模拟、关闭设备会话与隧道、恢复 remoted、退出 GeoPort 服务，并自动关闭当前 GeoPort 页面。不关闭浏览器或其他标签页，不删除已保存的基准与半径。停止或清理失败时保留页面并显示失败原因。

## 当前行为（已验证）

`src/static/lite.js` 的退出处理调用 `/exit`，随后禁用控件并显示“GeoPort 已退出，可以关闭此页面”，没有调用页面关闭。`src/main.py` 的 `/exit` 清理设备与隧道后退出服务。没有页面关闭后的延时退出机制。

## 浏览器约束（已验证规范，未实测）

`window.close()` 受浏览器限制。HTML 规范允许关闭由网页创建的窗口，或只有一条会话历史记录的顶层页面；不能保证所有 Safari/Chrome 标签页均可关闭。参考 [HTML Standard 的 close 规则](https://html.spec.whatwg.org/multipage/nav-history-apis.html#dom-window-close)。

目标仍是自动关闭当前页面。实现前需验证 APP 默认打开方式、手动打开、刷新和地图模式切换。浏览器拒绝关闭时的推荐回退：服务正常退出，页面显示“服务已退出，请关闭此页面”。该回退尚未由用户确认；不通过改变浏览器安全设置绕过限制。

## 关闭页面后延时退出（候选方案，假设）

可以用页面与后台的连接状态跟踪打开的 GeoPort 页面，由服务端执行延时计时。推荐 WebSocket 连接计数：最后一个 GeoPort 页面断开后启动倒计时；倒计时内重新打开页面则取消退出。推荐延时 120 秒，用户尚未确认数值，也尚未要求实现本项。

要求：仍有任一 GeoPort 页面打开时不退出；刷新、切换标签和页面暂时进入后台不应误退出；浏览器崩溃、后台冻结、Mac 睡眠与唤醒需验证。倒计时到期采用与按钮相同的停止模拟及资源清理流程，保留用户配置。

## 实现前待确认

1. 自动退出延时是否采用推荐的 120 秒。
2. 浏览器拒绝自动关闭页面时，是否接受保留退出提示页面。
