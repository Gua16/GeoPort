# GeoPort Lite · macOS 实机测试包

目标：Apple 芯片（arm64），macOS 15 或更新。包含 Python 与依赖，不需要安装 Python。
源码基于仓库 2.3.3，简洁版测试包版本为 0.1.1，并非上游 4.0.2 正式发行版。

## 安装与首次启动

1. 打开 `GeoPort-Lite-macOS-15-arm64-test.dmg`。
2. 将 `GeoPort Lite.app` 拖进 `Applications`。
3. 启动该应用。浏览器将在本地服务就绪后打开简洁界面。
4. 如果 Gatekeeper 阻止打开，在“系统设置 → 隐私与安全性”中对这个应用选择“仍要打开”，并按系统提示确认。

这是临时签名的测试包，未经过 Apple Developer ID 签名或 Apple 公证。不要关闭整个系统的 Gatekeeper，也不需要安装证书或在聊天中提交任何密码。DMG 附有 SHA-256 校验文件，可在下载目录使用 `shasum -a 256 -c GeoPort-Lite-macOS-15-arm64-test.dmg.sha256` 校验完整性。

如需要管理员权限（通常是 iOS 17+ 的隧道连接），先在页面点“退出 GeoPort”，然后打开 DMG 中的 `Start with Admin.command`。脚本在本机终端请求 sudo 密码，浏览器仍由普通用户打开。必须先把应用拖进 Applications；保留这个脚本以便以后启动。若系统阻止该脚本，同样使用系统的“仍要打开”确认。

普通与管理员启动共用 `~/Library/Application Support/GeoPort/config.json`。退出软件或停止模拟不删除基准坐标。关闭浏览器标签页不等于退出服务器；用页面底部的“退出 GeoPort”按钮停止并退出，管理员终端也可使用 Control-C。

## 推荐实机测试顺序

1. 保存基准坐标 A 和半径 300 米，不连接设备也可以保存。
2. 退出应用后重新打开，确认 A 和半径仍在，且未自动向 iPhone 应用定位。
3. 接入 USB，解锁并信任电脑，必要时开启设备开发者模式。
4. 连接设备并设置基准坐标，观察 iPhone 地图位置。
5. 连续点击多次随机偏移，观察每次仅变化一次，所有点均在 A 周围，A 保持不变。
6. 恢复基准、停止模拟，确认设备位置效果；拔出设备后尝试设置，确认出现失败提示。
7. 断开互联网，重复已经完成配对和准备的设备测试；首次设备准备及旧 iOS 开发者镜像仍可能需要联网。
8. 打开地图模式，回归原地图设置与停止。

若异常，请记录 macOS 版本、iOS 版本、普通/管理员启动方式、USB/Wi-Fi、页面错误原文，以及可以复现的步骤。管理员启动时还可复制终端中相关错误段落。不要提供密码或设备配对密钥。

安装包在原生 macOS runner 上验证启动、界面资源、配置写入、进程重启和退出；runner 没有实体 iPhone，设备定位结果由实机测试确认。

## USB 隧道诊断（2026-10-12 Codex）

已验证：macOS 27.0.1 (26A434)、iOS 27.0.1 (24A446)、USB、Python 3.12、锁定的 pymobiledevice3 4.4.0。

普通用户连接时，暂停 `/usr/libexec/remoted` 抛出 `PermissionError → psutil.AccessDenied → AccessDeniedError`。旧线程吞掉异常，页面等待满 30 秒才显示超时。修复版记录完整 traceback，并将原异常类型和原因传回连接请求；本机普通权限请求在 0.133 秒返回 HTTP 502。管理员权限由本机 Terminal 的 sudo 提示获取，不在页面或聊天中输入密码。

隧道启动成功后恢复 remoted，再发布 RSD 地址。创建服务、握手、取消或启动失败时执行恢复和服务关闭；清理失败记录日志，不覆盖原始异常。启动超时上限仍为 30 秒。USB TCP 复用连接请求创建的 lockdown。

管理员源码实机验证：连接成功；设置基准 `23.1291, 113.2644`；300 米半径内随机偏移 5 次；恢复基准；停止模拟；断开并再次连接；再次设置、停止、断开。remoted 最终未暂停。手机地图画面和恢复后的真实 GPS 坐标未目视验证。Wi-Fi 和旧 iOS QUIC 未做实机验证。

本次修复和验证结果见 [`STATUS.md`](../STATUS.md)。已安装的测试包不会因源码修改自动更新；使用修复源码启动，或重新构建安装包。
